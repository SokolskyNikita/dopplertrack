# Re-fitting `detect`'s flyovers in narrower windows (2026-11-03)

**Question.** `detect` fits each flyover in a 240 s window. Does re-fitting it in a narrower automatic window, with no hand choices, give fits that pass the default gates on both recordings?

**Change.** No hand choices anywhere. Development data.
- **Window**: from `detect`'s own fit, either ±55 s around its CPA (as wide as the README's hand windows) or ±2·d/v.
- **Band**: 0.85 f_post to 1.15 f_pre.
- **Gates**: left at their defaults.

| Re-fit | Oyster Bay, `detect`'s top two | Eagle cam, README's two events |
|---|---|---|
| none (`detect`'s 240 s windows) | filtered out at the true location | 1st of 607, 917 m, 2.5 % |
| ±55 s, brightness objective | 1st of 465, 123 m, 6.0 %, 48,237 candidates | 70th of 604; a wrong pair 14 km away wins by 20 % |
| ±2·d/v, brightness objective | 1st of 403, 123 m, 7.7 %, 48,036 | true pair filtered out everywhere |

- With the contrast objective, the re-fits fail at the true location on both recordings.
- On the eagle cam, the ±55 s event-1 window raises the wrong pair's event-1 score from 6.8 to 10.4, but the true pair's only from 6.2 to 7.1. The 240 s window's flat tails were what told those two pairs apart.

**Outcome: reverted.** Narrowing the window removes the dilution that hurt Oyster Bay, but also the evidence that protected the eagle cam, so neither window rule tested suits both recordings. PLAN Phase 2 follows up by masking the unreliable stretches of each track instead of cropping to a fixed width.

**Scripts:**
- `rewindow.py` re-fits each flyover and scores it at the true location.
- `swfl_truth.py` shows which filter each fit trips at the nest.
- `summarise.py`.

**Outputs:** `runs/2026-11-03-rewindow/`.
